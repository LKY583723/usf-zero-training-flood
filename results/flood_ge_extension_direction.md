# 扩展方向决策（2026-09-07）· 城区双分支评估 → 走分析深度

> 背景：用户想扩展 v4（config F vs CNN，GRSL 级）。最初想"结构上加强验证门"。
> 仓库存档已证否多数杠杆（`flood_ge_improve_attempts.md`、`flood_ge_explore_negatives.md`）。
> 本次按计划做城区分支（记录在案的"真改进方向"）可行性实验，数据见：
> - `docs/03_结果/flood_ge_urban_branch_calib.md`（Phase 1 校准）
> - `docs/03_结果/flood_ge_urban_branch_eval.md`（Phase 2 测试集）

## Phase 1 · 校准（官方 train+valid，4678 洪象限，523,738 城区 GT 像素）

- 纯相干下降检测器（pre_coh>P & Δγ>D）**全线精度崩塌**：最优 F1 仅 0.084（coh_vh）。
- 加**亮度约束 post_vv>−3 dB** 后大幅改善：`coh_union P=0.6 D=0.3 pm=−3` → 城区 F1 **0.219**（P=0.177, R=0.288）。
- 论文/代码的 S_urban 常数 (0.5,0.2) / (0.6,0.25) 在无亮度约束的 coh_union 内 F1 仅 0.017/0.030 → 说明旧规则缺了"亮回波"这道关键约束。

## Phase 2 · 测试集验证（4 场景，class-aware GT==2，检测语义 F|U）

**结论：方向 A（零训练城区分支）不成立。**
- 信号是"物理可选"的：接入分支后城区**召回**从 0 升到 0.3–0.4 → 相干+亮回波确实命中城区洪水。
- 但**空间不可选**：分支在全场景铺开数十万级 FP（精度 0.001–0.006）→ class-aware 城区 F1≈0。
- 校准集 0.219 是"仅统计洪水象限、且 03_FU 城区 tile 占主导"的乐观偏差，不迁移到真实稀疏城区场景。
- 根因（机制）：城区洪水检测缺的不是"标记信号"而是**空间先验/定位**（建筑区范围、邻接水体），零训练固定阈值无法提供 → 需要学习的定位或外部地图先验。

## 附带诊断（对论文有用）

- **open 口径不受城区影响**：config F 下 openF1 标准 == 城区中性（每场景差值 +0.000）→ config F 本就不检城区，0.654 不是靠忽略城区"刷"出来的。
- 城区相干信号作为 **GT 级标记**仍然成立（存档 `flood_ge_explore_negatives.md`：城区 GT Δγ>0.2 占 82–99% vs 开放 TP ≤27%）——这是"机制边界"分析的素材。

## 决策：扩展走 B（分析深度长文）

扩展产物不以"新方法/更高 F1"为卖点，而以 **机制 + 边界 + 诚实负面证据** 的完整化为卖点，
可支撑 JSTARS 级长文。候选内容（Phase 3 逐个出数据）：
1. **验证门分层 FP 消解表**（int∩chg → −12dB → conn≥500 每层砍掉多少 FP、召回掉多少）——量化"假阳率相乘"机制。
2. **计算效率正式对比**（config F ~21.5 ms/tile CPU vs CNN 训练 6.4 h+）。
3. **城区机制负结果**（本文件）：相干是城区标记但空间不可选 → 说明双类零训练需换目标函数/加先验。
4. **open 口径完整性诊断**：城区 GT 不压低 open F1。
5. 以上进 Discussion/机制小节或补充材料，不破坏 v4 主口径。
